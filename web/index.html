Keep your work
After each run, the project’s sources and data are saved to this browser. Stopping the runner first saves again, and the next start restores that project. Editor drafts are saved independently as you type. Browser storage can be cleared or evicted; download a backup for work you want to keep permanently. Files outside /root/work/go-foundry need a manual export.
The terminal tools below export the current live project or restore an uploaded archive. Choose Start runner first if needed.
cd /root/work && tar czf /root/go-foundry-work.tar.gz --exclude='go-foundry/.bin' --exclude='go-foundry/.go-cache' --exclude='go-foundry/.go-path' go-foundry && export_file /root/go-foundry-work.tar.gz
Open Linux terminal and upload your work archive using its upload control. Then choose Restore uploaded archive. This replaces the live project; the replacement is saved after the next Run or Stop runner. The command is:
tar xzf /root/go-foundry-work.tar.gz -C /root/work && cd /root/work/go-foundry && ./run db-read
Restoring replaces the live project with your exported source and data. Export current work first if needed. Saved editor drafts remain separate; Run sends the current editor file to the guest.

Code runner
The compiler and Linux run on this device. The guest is configured with 768 MiB RAM; browser and compiler overhead require additional memory. The header reports Ready after Linux confirms that its workspace and file share are prepared.
The runner saves project files and data after every run and before stopping. It restores the saved project at its next start. If saving fails, automatic stopping is cancelled. Browser editor drafts are kept separately.
Background tabs may be suspended by your browser. The idle check resumes when the page can run again.


Stop the code runner?
The project’s source files and data will be saved in this browser before Linux stops. Its next start restores those files. Files outside the project directory need a manual export.


App status
The first three Go chapters use a real compiler in browser Linux. The terminal, v86 emulator, firmware, Linux kernel, Go SDK, prepared cache and examples are served by this course. No third-party runtime host is used.
Starting Linux needs internet access to load the runtime files. Saved project files alone do not make the course available offline. No complete offline Linux copy is offered. Downloaded source and work archives can be kept independently.
Version and implementation details
Lesson jobs receive no interactive input; use the optional terminal for input-reading programs. The terminal runs inside this course. Run transfers the current file through a guest-only share, then invokes Go. Use its upload control to restore an archive, and export_file in Linux to download files.
